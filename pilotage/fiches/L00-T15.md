# L00-T15 Preuve : adresse du visiteur derrière le relais d'hébergement

## Ce qu'il faut livrer

Document : étude du code du kit (`src/lib/comptes/reseau.ts`, réglage `COMPTES_PROXY_FIABLE`) et essai local en `pnpm start` avec un en-tête falsifié : l'adresse réelle du visiteur est-elle lisible de façon fiable (en-tête de confiance, relais connu), sans qu'un visiteur puisse la falsifier ? Le comportement derrière le vrai relais d'hébergement reste « NON PROUVÉ » jusqu'au serveur d'essai. Verdict pour l'adresse transmise au journal de la console (qui la protège par sa clé de période) et pour les limites contre les abus ; en mode intégré, l'adresse est celle que le portail a vérifiée.

## Exigences visées

- R190 : journal d'audit qui ne se modifie pas
- R200 : limites contre les abus

## Cas limites à tester

en-tête falsifié par le visiteur ; deux relais en chaîne ; visiteur derrière deux relais de confiance (lecture de gauche à droite) ; adresse IPv6 (forme canonique) ; plusieurs comptes derrière la même adresse d'entreprise (limite par compte, pas seulement par adresse).

## Tests

Contrôles de relecture du document (pas de test de code ; chaque ligne est vérifiée par le relecteur, le document ne peut pas être fait sans preuve : il écrit NON PROUVÉ) : « R190 — le document dit si l'adresse du visiteur est lisible de façon fiable pour le journal, ou NON PROUVÉ » ; « R200 — le document donne le verdict pour les limites contre les abus ». Condition de L01-T20 (et de L01-T06 en mode autonome).

## Pourquoi sensible

journal « depuis où » et limites (sécurité).
