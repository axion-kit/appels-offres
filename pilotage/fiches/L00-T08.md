# L00-T08 Preuve : connexion de la personne aux plateformes et alerte e-mail

## Ce qu'il faut livrer

Document : pour 5 plateformes au moins de profils d'acheteurs, au choix de l'auteur parmi les plateformes publiques les plus utilisées (nommées dans le document, sources publiques), ce que la personne doit faire elle-même, ce que l'outil peut noter (déclaration), si une alerte e-mail existe ; confirme qu'aucun mot de passe n'est nécessaire à l'outil. Pour chaque alerte e-mail : expéditeur technique, présence d'une signature DKIM, structure du message (champs repérables), liens présents ; un modèle FICTIF de chaque forme est écrit pour les essais du lecteur d'alertes (aucun message réel recopié). Document public sans réponse brute, sans nom d'acheteur, de ville ni de personne.

Règle réseau : les lectures réseau ne se font jamais depuis la session de l'auteur ; seul le workflow manuel `.github/workflows/preuves-reseau.yml` lancé par le directeur lit le réseau, et il ne couvre pas les plateformes de profils d'acheteurs. Cette fiche n'a donc aucun constat réseau : pour chaque point qui demanderait de lire une plateforme ou de recevoir une vraie alerte, le document écrit « NON PROUVÉ — sortie du workflow absente » et décrit ce qu'il faudrait constater ; ce que l'auteur sait par ailleurs est marqué « à vérifier », jamais présenté comme constaté. Les modèles fictifs d'alerte sont écrits quand même (ils servent aux essais). La fiche reste faite avec ces constats. Fichier à lire : `SPEC.md` (R161).

## Exigences visées

- R161 : Mes comptes sur les sites d'appels d'offres

## Cas limites à tester

plateforme sans alerte ; compte à double facteur ; plateforme dont l'alerte e-mail vient d'un expéditeur technique sans signature DKIM ; entreprise à plusieurs établissements : un compte par établissement sur la plateforme ; alerte reçue en plusieurs exemplaires (doublon).
