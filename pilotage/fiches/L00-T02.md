# L00-T02 Blocs de planche manquants : onglets, case, bouton inactif, liste de pièces

## Ce qu'il faut livrer

Les types de blocs de `ecrans.ts` et leur rendu dans `src/components/EcranVue.tsx` (le moteur de planche du kit ; exception permise par cette fiche) gagnent 5 sortes : `onglets`, `case` (jamais cochée d'avance), `bouton-inactif` (avec sa raison écrite), `liste-pieces` (chaque pièce demandée avec son état et, si elle manque, sa raison), `ligne-etape` (« Étape : … · … »). La carte et le calendrier restent montrés par leur liste équivalente. Aucun écran n'est encore ajouté.

Formes à écrire dans le type `Bloc` (à ajouter aux 5 sortes du kit, qui restent) :
```
| { type: "onglets"; onglets: [string, ...string[]]; actif: number }          // tableau jamais vide (refus par le type)
| { type: "case"; libelle: string }                                           // aucune propriété "cochee" : toujours rendue décochée
| { type: "bouton-inactif"; bouton: string; raison: string; secondaire?: boolean }  // raison obligatoire (refus par le type)
| { type: "liste-pieces"; pieces: { nom: string; etat: string; raison?: string }[] }
| { type: "ligne-etape"; etape: string; mention?: string }                    // rendu « Étape : <etape> · <mention> »
```
Le type `Ecran` gagne un champ facultatif `numero?: number` (numéro de l'écran sur la planche, posé explicitement par chaque fiche de planche ; certains écrans n'en ont pas). `EcranVue.tsx` l'affiche devant le titre s'il existe.

Validation : une fonction exportée de `src/design/ecrans.ts` (et non de `src/lib/design/controle.ts`, non autorisé ici) :
```
export function problemesEcran(e: Ecran): string[]   // liste vide = bon
```
Elle renvoie un problème si l'écran a plus de 7 blocs, plus d'un bouton plein (un bouton plein = un bloc `action` ou le bouton d'un bloc `formulaire` ; `bouton-inactif` n'en est pas un), un bloc `onglets` dont `actif` sort du tableau, ou un identifiant vide. Elle est appelée sur un écran à la fois ; les fiches de planche suivantes l'appellent dans leurs tests sur tous leurs écrans.

## Exigences visées

- R13 : une chose à la fois
- R24 : aucun bouton mort
- R17 : un seul mot par étape

## Cas limites à tester

case rendue non cochée ; bouton inactif sans raison refusé par le type ; onglets vides (refus par le type) ; écran de 8 blocs (refusé par `problemesEcran`) ; écran avec deux blocs `action` (refusé) ; liste de pièces de 50 lignes sans débordement ; 7 blocs au plus par écran ; le bloc `case` accepte un libellé qui porte le nom de l'entreprise (« … au nom de <entreprise> ») ; le bloc `bouton-inactif` couvre aussi le bouton secondaire à côté du bouton plein (« Retenir sans commencer ») ; nouveau bloc `ligne-etape` (« Étape : … · … ») ; le rendu d'`EcranVue` ne lit que des variables (`--c-*`, `--couleur-*`) : le même écran rendu avec les deux jeux n'a aucune couleur écrite en dur.

## Tests

`src/design/ecrans-blocs.test.tsx` › « R13 — problemesEcran refuse plus de 7 blocs et plus d'un bouton plein » ; « R24 — un bouton inactif affiche toujours sa raison » ; « R17 — le bloc ligne-etape affiche l'étape et sa mention » ; « R13 — un écran rendu avec le jeu console puis le jeu bleu v23 ne contient aucune couleur hors des jetons » ; « R24 — un bloc case n'est jamais rendu coché d'avance » ; « R13 — un bloc onglets vide est refusé par le type » (avec `// @ts-expect-error`) ; « R13 — le numéro d'un écran est affiché devant son titre quand il existe ».
